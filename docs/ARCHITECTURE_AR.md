# معمارية خادم باء للغات البرمجة

## القرار

`Baa-LSP` هو خادم اللغة الرسمي للغة باء، و`Qalam` هو بيئة التطوير المخصصة
لباء.

استفاد التصميم من الأفكار العامة في خطة تكامل LSP المرفقة: فصل النقل عن
المستند، وتقسيم العمل إلى حزم صغيرة، وربط النتائج بإصدار المستند، واختيار
القدرات بعد `initialize`. جرى تكييف هذه الأفكار لتخدم منتج قلم المخصص لباء.

## حدود الملكية

```text
قلم       = التحرير والعرض والتنقل وتجربة المستخدم
Baa-LSP   = بروتوكول LSP وحالة المستند وتحويل المواضع والطلبات الدلالية
باء       = الحقيقة النحوية والدلالية والرموز والأنواع والتشخيصات
تكوين     = المشروع والبناء والتشغيل والاختبار والتنظيف
نظم       = التجميع وإنتاج الملفات الكائنية
```

لا يبني `Baa-LSP` محللًا موازيًا للغة. يبدأ كجسر دائم فوق عقود مصرف باء، ثم
يمكن استبدال تشغيل العملية بواجهة مكتبة أمامية من دون تغيير بروتوكول العميل.

## البنية

```text
Qalam
  └─ BaaLanguageClient
       ├─ LspMessageFramer
       ├─ JsonRpcConnection
       ├─ BaaDocumentSession
       └─ Feature Controllers
                    ↕ stdio
Baa-LSP
  ├─ StdioTransport
  ├─ MessageFramer
  ├─ BaaLanguageServer
  ├─ DocumentStore
  ├─ PositionEncoding
  └─ BaaCompilerBridge
                    ↕ argv + stdin + JSON
Baa reference compiler
```

الخادم بلا واجهة رسومية وبلا اعتماد على Qt. يعتمد المسار التنفيذي على C++23
وواجهات العمليات الأصلية في Windows وLinux، ويستخدم `nlohmann/json` لمعالجة
رسائل JSON. يبقى Qt داخل قلم لأنه تطبيق الواجهة وعميل LSP، ولا ينتقل إلى الخادم.

## قواعد النقل

- النقل الأول هو `stdio` فقط.
- كل رسالة تستخدم `Content-Length` بالبايت، وليس بعدد محارف Unicode.
- لا يكتب الخادم أي سجل إلى `stdout` خارج رسائل LSP.
- السجل البشري يذهب إلى `stderr`، والنتائج القابلة للآلة تبقى JSON.
- حجم الترويسة والجسم محدودان، وتُرفض الرسائل المشوهة بدل التخمين.

## دورة الحياة

1. يستقبل الخادم `initialize` ويعيد القدرات الفعلية فقط.
2. يستقبل `initialized` قبل فتح المستندات.
3. يستخدم مزامنة نص كامل في الإصدار الأول.
4. يزيد العميل رقم الإصدار عند كل تغيير.
5. يرفض الخادم تغييرًا لا يزيد على الإصدار المقبول.
6. يوقف `shutdown` قبول العمل الجديد.
7. ينهي `exit` العملية بنجاح فقط إذا سبقه `shutdown`.

## التشخيص الحي

عند فتح مستند أو تغييره يمر النص غير المحفوظ هكذا:

```text
didOpen / didChange
        ↓
DocumentStore(version, text, uri)
        ↓ مهلة قصيرة واستبدال الطلب الأقدم
baa --check --diagnostics=json --source-stdin=<المسار المنطقي>
        ↓
diagnostics-json-v1
        ↓
تحويل بايتات UTF-8 إلى مواضع UTF-16
        ↓
textDocument/publishDiagnostics(uri, version)
```

لا تكتب ملفات ظل داخل المشروع. النتيجة لا تُنشر إذا تغير إصدار المستند أو
أُغلق أثناء التحليل. عند الإغلاق يرسل الخادم قائمة تشخيصات فارغة لإزالة
العلامات من قلم.

## المواضع والمسارات

- يستخدم LSP سطورًا ومحارف تبدأ من الصفر.
- يستخدم الإصدار الأول `UTF-16` صراحة لأنه يطابق `QString` و`QTextCursor`.
- يستخدم مصرف باء نطاقات تبدأ من الواحد وإزاحات بايتات UTF-8.
- يتم التحويل داخل `Baa-LSP` فقط؛ لا يكرر قلم هذا المنطق.
- تتحول المسارات عبر URI قياسي، مع اختبارات لمسارات Windows والفراغات
  والأحرف العربية.

## فصل الأدوات عن LSP

الإكمال وHover والتعريف والمراجع وإعادة التسمية والتشخيصات مسؤولية LSP.
البناء والتشغيل والاختبار والتنظيف تبقى عبر تكوين. قد يمرر قلم سياق الهدف
ومسارات التضمين إلى الخادم، لكنه لا يحول أوامر تكوين إلى طلبات LSP.

## مراحل القبول

1. نقل وإطارات واختبارات رسائل جزئية ومتعددة ومشوهة.
2. دورة حياة JSON-RPC وLSP.
3. مستند واحد بإصدارات كاملة وتشخيصات حية.
4. ربط قلم وإزالة الاستدعاء المباشر للمصرف من واجهة التحليل.
5. رموز وإكمال وHover بعقود باء مهيكلة.
6. تعريف ومراجع وإعادة تسمية وإجراءات كود.
7. مساحة عمل وتكوين وإلغاء واستعادة بعد تعطل الخادم.
8. بوابات Windows/Linux ومسارات عربية وضغط تحرير وتغليف.
